# Demo and submission ledger

This folder is the running source of truth for what must be shown, recorded, and
submitted. Items move to “proved” only when a live run, screenshot, transcript, or
committed test result exists.

## Canonical demo promise

A product lead and an engineering lead share one launch-scope decision with an agent.
The product lead selects an option, which changes the page’s actual WebMCP tool set. The
engineering lead changes capacity in a second window. An agent write based on the old
revision is rejected with that collaborator-authored diff, the agent adapts, and it
prepares a decision card. The product lead edits or ratifies it in the UI; a downstream
launch artifact and the provenance timeline update.

## Required video evidence

- [ ] Working product appears in the first 10–15 seconds.
- [ ] Normal human UI is visibly useful without developer tools.
- [ ] Agent discovers tools from the live page with no connector or OAuth setup.
- [ ] Page selection visibly changes the actual discovered tool set.
- [ ] Second attributed participant changes a numeric constraint in another window.
- [ ] Old-revision agent write is rejected with the exact human-authored diff.
- [ ] Agent re-inspects and recovers without manual repair.
- [ ] Agent prepares; a human explicitly edits/ratifies in the UI.
- [ ] One downstream artifact/capability changes after ratification.
- [ ] Provenance distinguishes human, collaborator, and WebMCP-originated work.
- [ ] Runtime is 2:59 or less and includes spoken narration.

## Submission evidence

- [ ] Public unrestricted live URL tested from a clean session.
- [ ] Public GitHub repository contains all source, MIT license, and run instructions.
- [ ] Devpost’s four written answers each map to concrete evidence.
- [ ] Public YouTube link plays without authentication.
- [ ] Native surface versions and setup are documented.
- [ ] Protocol, browser, and agent-eval results are committed and sanitized.
- [ ] Five consecutive production hero runs pass after reset.
